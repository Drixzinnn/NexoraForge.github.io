BYOK feito direito: criptografia de chaves de usuário

Guardar a chave do usuário é assumir risco. Veja como reduzir esse risco ao mínimo.

Quando o usuário entrega a própria chave de API, você passa a guardar um segredo que não é seu. Se o banco vazar, as chaves vazam junto. Isso é inaceitável — e evitável.

AES-256-GCM, não hash

Senha se guarda com hash, porque você nunca precisa ler a senha de volta. Chave de API é o contrário: você precisa dela em texto puro para chamar o provedor. Portanto, criptografia simétrica — e com autenticação, para detectar adulteração.

GCM fornece as duas coisas: confidencialidade e uma tag de autenticação que falha se alguém alterar o texto cifrado.

iv  = randomBytes(12)              // único por registro
cifra = AES-256-GCM(chave, iv)
tag = authTag()                    // detecta adulteração
salvo = base64(iv).base64(tag).base64(cifra)

Regras que não se negociam

A chave de criptografia vive em variável de ambiente, nunca no código nem no banco. O IV é novo a cada registro — reutilizar IV em GCM destrói a segurança. E a chave em texto puro nunca volta ao navegador: a interface recebe apenas os quatro últimos caracteres, para o usuário saber qual chave está salva.
